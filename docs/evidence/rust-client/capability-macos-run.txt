The app's nsh.json declares only hosts: ["127.0.0.1"]. Echo server: the repo's own

Outcome, verbatim below: D2 (undeclared host localhost) returned 200 — NOT refused;
D3 (redirect to refused.invalid) was followed into real DNS ("A server with the
specified hostname could not be found") — NOT refused by capability. On 0.4.0 the
native host never attaches a rust root's capabilities
(nsh-platform-macos 0.4.0 src/native.rs:270: `App::Rust(_) => Policy::default().access()`,
and nsh-core access.rs:1147: `is_unrestricted` skips the check). Refusal is provable
only through the TSX/QuickJS path (docs/decision.md, experiment 1). The client's
refused-by-capability classification is unit-proven in crates/nsh-http/tests/errors.rs
against the engine's exact refusal message.
